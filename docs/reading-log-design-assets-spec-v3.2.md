# わたしの ほんだな — デザイン・実装用素材仕様書 v3.2

- 作成日: 2026-11-07
- 対象: 小学1年生向け読書記録Webアプリ
- リポジトリ: `yasu-sensei/reading-log`
- 公開先: https://yasu-sensei.github.io/reading-log/
- 文書の位置付け: **素材制作とUI実装の基準文書**。採用済み事項と提案事項を区別する。
- ステータス: デザイン方針確定／素材内訳と寸法は実装前の提案

## 1. 最優先の確定事項

1. デザインは**木製の本棚を中心とした、明るく温かいファンタジー図書館／ゲームUI風**。
2. 2026-11-07にチャットで生成・ユーザーが「採用します」と明示した、木製本棚、蔦、ランタン、フクロウ、金色の縁取り、カラフルな絵本、緑色の読み取りボタン、5つのメダルを含む**採用済み完成イメージ**を画風基準とする。生成ID: `773b0a55-a718-4fdc-a09e-735392b03f1a`。**この生成IDは参照用メタデータであり、GitHubに画像本体を保管したことは意味しない**。画像本体は別途リポジトリへの登録が必要。
3. 木目・立体的な本棚・主要なゲームUIは**専用画像素材を制作**する。CSSだけで木目・石積み・立体感を描いて完成としない。CSSは配置・文字・レスポンシブ・状態表現に使用。
4. 石造りの魔法図書館案は**不採用**。木製の本棚を採用する。
5. **実際の本の表紙画像**を動的に表示し、タップで詳細を開ける。採用イメージ中のサンプル本・児童名・冊数は固定素材に焼き込まない。
6. 本は左から右へ並び、幅いっぱいになったら次の段へ。本が増えたら段が増える。横向きタブレットを主対象とし、1段**約5〜7冊**の大きな表紙を目安とする。
7. 表紙は少し立体的に見せるが、絵や文字が見づらくなるほど傾けない。
8. メダル達成条件は**異なる本10・20・30・50・100冊**。未獲得は控えめ、獲得済みは鮮やかに表示。
9. 既存のISBN読み取り、書誌情報、読書記録、表紙写真、詳細表示、再読記録を維持する。既存の保存キー `reading-log-v24` と IndexedDB `reading-log-covers` / `covers` を変更・削除しない。
10. 採用済み素材は承認なしに再生成・差し替えしない。

## 2. 画面構成

- 上部: タイトル看板「わたしの ほんだな」、児童名パネル、設定アイコン。
- 情報領域: 「よんだ ほん」冊数、5種類の達成メダル、目立つ「ほんを よみとる」ボタン。
- 主領域: 表紙が主役の木製本棚。段数はデータに応じて増加。縦スクロール可能。
- 装飾: 蔦、ランタン、フクロウ、魔法の本、小さな光。**表紙・操作部品・文字を隠さない**。
- 画面上部を過度に大きくせず、タブレットで本棚が見える面積を優先する。
- スマートフォン縦画面でも破綻しないよう最低限のレスポンシブ対応を維持する。

## 3. 制作提案: 全22種類の素材

> 以下の**22種類・推奨寸法は提案段階**。個別の画風、画像の切り分け、実サイズ、透過状態は制作時に検証して確定する。

| ID | 素材 | 用途・要件 |
|---|---|---|
| A01 | 本棚の基本段 | 最優先。**本を置く領域が空**の棚。繰り返し利用 |
| A02 | 本棚の上部装飾 | 最上部のみ。木彫りと金色の縁取り |
| A03 | 本棚の左右の柱 | 両端を囲む。左右反転可能か検証 |
| A04 | 本棚の最下部 | 棚の最終段を自然に終える |
| A05 | 図書館の背景 | 明るい壁、窓、自然光、植物。中央の視認性を確保 |
| A06 | タイトル看板 | 文字なし。タイトルはHTML表示 |
| A07 | 木製棚板 | 幅に合わせて繰り返し／端と中央を分割可能な構造 |

### B. 読書情報・操作: 5種類

| ID | 条件 | デザイン |

| C02 | 20冊 | 銀の本メダル |

## 4. 推奨制作サイズ・画像形式（暫定）

| 区分 | 推奨サイズ | 形式 |
|---|---|---|
| A05 背景 | 1920×1080px | WebP |
| A01 本棚の基本段 | 1600×400px | WebP（必要に応じ透過） |
| A07 棚板 | 1600×100px | 透過PNG／WebP |
| A02/A03/A04 | 部品に応じて個別設計 | 透過PNG／WebP |
| A06/B01/B02 | 約800×250px | 透過PNG／WebP |
| B03 ボタン | 約800×240px | 透過PNG／WebP |
| C01〜C05 | 256×256px | 透過PNG／WebP |
| B04/B05/D01〜D05 | 約256〜512px | 透過PNG／WebP |

- **透明が必要な画像は背景アルファ0**を検査。背景画像は透明でなくてもよい。
- 幅の変化がある棚板・パネル・ボタンは、単純引き伸ばしで歪ませない。端・中央の分割や9-slice等を検討。
- 画像の重さ、表示品質、ロード速度を実機で検証。素材台帳にID、用途、サイズ、形式、透過、版、採用状態、ライセンスを記録。
- 画像に児童名・冊数・可変文言を焼き込まない。

## 5. 本棚の動的実装

1. A01を空の棚として使い、表紙写真は**別のHTML要素**として上に配置する。
2. 表紙は本ごとにクリック／タップ可能。読書記録に登録された**異なる本**だけ表示。
3. 横向きタブレットでは約5〜7冊／段を目標に、実際の表示幅から段数と列数を決める。
4. 画面幅に応じて段を折り返す。段数に上限を設けず、縦スクロールで閲覧。
5. 表紙・棚板・柱の位置ずれが起きないよう、**棚の描画と本のグリッドを同一のレイアウト基準**で管理する。
6. 新しく読んだ本を先頭に配置。再読しても表紙は増やさない。
7. 表紙画像がない場合の代替表示は、既存動作を維持し、デザインのみ別途決定。
8. 既存の「もっと みる」等の段階表示がある場合は、全件表示との兼ね合いを実機検証で決める。

## 6. 制作順序と承認ゲート

1. **第1段階：A01〜A07 本棚**。最初にA01の空の棚を作り、画風・奥行き・実際の表紙の収まりを確認。承認後、棚板・柱・上下部・背景・看板を制作。実機で段の増加と操作を検証。
2. **第2段階：B01〜B05 UI**。冊数・名前・ボタン・アイコンを制作。日本語テキストはHTMLで重ね、押しやすさを確認。
3. **第3段階：C01〜C05 メダル**。統一した画風、達成条件、未獲得・獲得状態を検証。
4. **第4段階：D01〜D05 装飾**。操作性を損なわない範囲で追加し、サイズ・読み込み速度を最適化。

各素材の標準工程：**採用画風参照 → 素材生成 → サイズ・透過・造形検査 → ユーザー承認 → GitHub登録 → アプリ組込 → 実機確認**。承認済み素材は勝手に再生成しない。
